# 口琴跟吹助手（HarmonicaFlow）— 实现计划

## Context（背景与目标）

用户需要一个**辅助口琴吹奏**的移动应用：屏幕上显示乐谱对应的"音符方块"，方块**随时间运动**，方块的**长度代表吹奏时值**，用户跟着方块吹奏即可。

要解决的核心问题是：**从"乐谱文件"到"可跟吹的动态音块"之间的自动转换**——即导入乐谱 → 自动解析 → 自动编配到具体口琴的孔位/吹吸 → 以时间轴动画呈现。

当前工作目录为空，属于全新项目。产品原则（来自用户偏好）：**后台复杂、前台极简**，减少用户操作成本（导入到开始跟吹尽量 1~2 次点击），整体**轻量**（依赖少、无后端、无音频）。

### 已确认的产品决策

| 维度 | 决策 |
|---|---|
| 口琴类型 | **全部支持**，内置 24孔复音 / 10孔布鲁斯 / 半音阶 三种预设，设置中可切换 |
| 导入格式 | **MusicXML（.musicxml/.xml/.mxl）、ABC 记谱、自有 JSON**；MIDI 延后 |
| 视觉呈现 | **横向卷轴 + 纵向落块 两种可切换** |
| MVP 范围 | **仅视觉跟吹**，不含音频/节拍器/录音 |

### 明确的非目标（本版不做）

- 不做音频播放、节拍器、录音对比（架构预留接口，后续可加）
- 不做 MIDI 解析
- 不做账号、云同步、分享
- 不做五线谱/简谱的排版渲染（只渲染音块时间轴）

---

## 技术选型

**Expo (React Native) + TypeScript + Expo Router**，可 `npx expo start` 后用 **Expo Go** 直接验证（所有依赖均在 Expo Go 内可用，无需自定义原生构建）。

### 运行时依赖（刻意最小化，共 6 个）

| 依赖 | 用途 | 说明 |
|---|---|---|
| `expo` + `expo-router` | 框架与路由 | 官方默认脚手架 |
| `react-native-reanimated` | UI 线程动画驱动时间轴 | Expo 内置，负责滚动位置，保证 60fps |
| `react-native-svg` | 绘制音块 | Expo Go 内置，矢量、体积小（对比 Skia ~6MB 更轻） |
| `expo-document-picker` | 选择乐谱文件 | 导入入口 |
| `expo-file-system` | 读取文件 + 曲库持久化 | 同时用于存储索引，省掉 AsyncStorage |
| `fast-xml-parser` + `fflate` | 解析 MusicXML / 解压 .mxl | 纯 JS、MIT、体积小 |

> 音名/MIDI 转换自行实现（12 半音表），不引入 `@tonaljs/*`，进一步减依赖。

### 渲染策略（轻量的关键）

- 时间轴滚动 = 对一个 SVG `<G>` 分组的**单点平移**动画（Reanimated 共享值驱动，仅在 UI 线程运行，不触发 React 重渲染）。
- **窗口化渲染**：只渲染可视区 ±1 屏范围内的音块（约 < 40 个 Rect），窗口集合每秒在 JS 侧低频率更新一次。避免超长歌曲产生上万节点。
- 横/纵两种视图共用同一套定位计算，仅交换 X/Y 轴语义。

## 数据模型

```ts
// 统一中间表示：与来源格式、口琴型号均解耦
type NoteEvent = { id: string; midi: number; startTicks: number; durationTicks: number; lyric?: string };

type Score = {
  id: string; title: string; composer?: string;
  ppq: number;              // 每四分音符 tick 数（默认 480）
  tempoBpm: number;
  timeSignature: [number, number];
  keySignature?: string;    // 如 "C" / "G"
  events: NoteEvent[];
  source: 'json' | 'abc' | 'musicxml';
};

// 口琴音阶排列：**纯数据驱动**，不做硬编码逻辑
type Hole = { index: number; blow: number | null; draw: number | null; push?: number | null }; // 存 MIDI
type HarmonicaLayout = {
  id: string; name: string; type: 'tremolo24' | 'diatonic10' | 'chromatic12';
  key: string; holes: Hole[];
  notes?: string; // 来源/存疑说明
};

// 编配结果：供渲染层直接使用
type TabNote = NoteEvent & {
  hole: number; action: 'blow' | 'draw' | 'push';
  noteName: string; feasible: boolean; // false = 该音在所选口琴上吹不出
};
```

> ⚠️ **关键风险**：24 孔复音口琴的音阶排列**因品牌/地区而异**（Hohner、Seydel、国产 24 孔并不一致，检索已证实）。因此排列只作为**可编辑的预设数据**存在，App 内提供"音阶表"页面让用户对照自己的琴校对/修改，绝不把排列写死在算法里。

## 实施步骤

### Phase 0 — 先规范文档（用户要求的先决条件）
产出 `docs/PRD.md` 与 `docs/TECH_DESIGN.md`：产品定位、用户主流程（导入 → 分析 → 跟吹）、界面说明、数据格式 schema、音阶预设表、编配算法说明。**提交用户确认后再进入编码。**

### Phase 1 — 工程初始化
`create-expo-app`（TypeScript + Expo Router 模板）→ 安装上述依赖 → 建立目录骨架 → 加入 1~2 首内置示例曲 JSON → 确认 Expo Go 可启动。

### Phase 2 — 核心模型与音阶预设
`core/model.ts`、`core/pitch.ts`、`core/layouts/*`。三种口琴各一份预设，字段与来源在文件头注释标注，便于用户校对。

### Phase 3 — 解析器（按优先级逐个交付）
1. **JSON**（最简单，先打通全链路）
2. **ABC**（纯文本，实现常用子集：头部字段 `X/T/M/L/K/Q`、音名与八度 `'` `,`、临时记号 `^_=`、时值 `2` `/2`、小节线与连音）
3. **MusicXML**（`fast-xml-parser` 提取 `part/measure/note` 的 step/alter/octave/duration/rest/chord/tie，divisions → tick；`.mxl` 用 `fflate` 解压）
统一入口 `parse(content, filename) → Score`，按扩展名分派。

### Phase 4 — 自动编配（"自动分析"的核心）
`core/arrange.ts`：Score → TabNote[]
- 建立 `midi → {hole, action}[]` 映射（复音琴同音多孔，需选优）
- 用**最小换孔移动代价**（贪心 + 前视，必要时 DP）在候选孔中选一个，避免大幅跳孔
- 标记 `feasible=false` 的音，页面顶部给出提示与建议（±八度移调 / 换口琴）
- 输出供渲染层直接消费的 TabNote[]

### Phase 5 — 时序与渲染
`player/timing.ts` + `usePlayback.ts`（共享值驱动的时间轴，支持倍速 0.5/0.75/1.0、起始留白 lead-in 约 2 秒）+ `ui/NoteTimeline.tsx`：
- 横向：X=时间（方块长度=时值），Y=孔位行，固定竖线为当前演奏位置，方块自右向左移动
- 纵向：方块自上而下落至底部判定线，方块高度=时值
- 颜色区分吹（blow）/吸（draw）；方块内标注孔号与音名
- 窗口化渲染，播放头随倍速移动

### Phase 6 — 页面与曲库
曲库首页（列表 + 一键导入）、跟吹页（时间轴 + 播放条 + 视图切换）、设置页（口琴预设切换 + 音阶表校对）。导入成功即持久化到 `expo-file-system`，主流程控制在"选文件 → 直接开始跟吹"两步内。

### Phase 7 — 联调与验证
见下节。

## 验证方式

1. **核心逻辑（无需 UI）**：`npx tsx` 跑一个临时脚本，用内置示例曲与一份 MusicXML 样本走通 `parse → arrange → TabNote[]`，打印表格对照人工检查（音高、时值、孔位、吹吸是否正确）。
2. **端到端**：`npx expo start` → Expo Go 打开 → 
   - 首页点内置示例曲 → 进入跟吹页，确认方块**随时间平滑移动**、**长度随时值变化**、横/纵视图切换正常；
   - 点"导入乐谱"选择一份 `.musicxml` / `.abc` / `.json` → 确认自动解析出音块并标记不可吹音；
   - 切换三种口琴预设，确认孔位/吹吸映射随之变化。
3. **性能**：用一首 3 分钟以上的曲子确认滚动无卡顿（验证窗口化与 UI 线程动画生效）。
4. **音阶表对照**：人工用实体口琴核对默认预设，不符处通过设置页修正（这是本产品最容易出错、也最需要用户参与验证的一环）。

## 交付顺序小结

`文档确认` → `工程骨架` → `模型/预设` → `JSON 解析打通` → `时间轴渲染（先横向）` → `ABC/MusicXML` → `编配优化` → `纵向视图` → `设置与持久化` → `联调验证`

每完成一个 Phase 可独立运行验证，避免大爆炸式集成。
