> 关联文档：[PRD](./PRD.md) · [TECH_DESIGN](./TECH_DESIGN.md)（§11 构建与部署） · [ARCHITECTURE](./ARCHITECTURE.md)（系统架构：AI 层分层、实时音频分期、提示词契约）

## 1. 目标与范围

### 1.1 目标

用户授权麦克风后，录制一段跟吹过程，系统给出**音准 / 节奏 / 稳定度 / 完整度**四项评分、逐音错误清单，以及一段**可执行的点评**。

### 1.2 分阶段范围

| 阶段 | 内容 | 是否需要"AI 模型" | 运行位置 |
|---|---|---|---|
| **一期** | 录音 → 本地音高/节奏分析 → 规则评分 + 规则模板点评 | 否 | 全离线，Expo Go 可验证 |
| **二期** | 把结构化评分交给 LLM，生成自然语言点评 | 是 | 需 BYOK 或轻量代理后端 |
| **三期** | 实时反馈（吹的同时显示偏高/偏低、抢拍/拖拍） | 否 | 需 development build + 原生音频库 |

**关键认知**：评分本身是**信号处理 + 数学**，不需要大模型；大模型只负责把结果"说得像人话"（第 8 节）。

### 1.3 非目标

- 不做自动改谱 / 自动纠错，不做教学课程体系。
- 不做多声部、和弦识别（一期按**单音假设**处理）。
- 不做云同步、账号体系、排行分享。

---

## 2. 用户流程

1. 从跟吹页或曲目页进入「评测」（独立页面，不侵入跟吹主流程）。
2. 选择评测范围：默认整曲，可选前 N 小节或指定小节。
3. 首次点击「开始评测」时申请麦克风权限。
4. **引导与校准**：给 4 拍预备拍（节拍器，可选开关），提示"预备拍结束后开始吹"。
5. 录音：显示计时与节拍；录制过程中不做实时分析。
6. 停止 → 本地分析（显示进度，目标 3 秒内）。
7. 结果页：总分 + 四维雷达/条形 + 逐音错误清单（点击错误可跳回跟吹页对应小节）+ 点评。
8. 可重录；历史记录本地留存。

## 3. 音频采集

### 3.1 依赖与权限（已核实）

```bash
npx expo install expo-audio
```

- `expo-audio` 属于 Expo SDK，**Expo Go 已内置**，一期可在 Expo Go 中直接验证。
- `app.json` 注册 config plugin：

```json
{
  "expo": {
    "plugins": [
      ["expo-audio", { "microphonePermission": "需要麦克风权限来录制并评测你的吹奏" }]
    ]
  }
}
```

| 配置项 | 作用 |
|---|---|
| `microphonePermission` | iOS 的 `NSMicrophoneUsageDescription` 文案 |
| `recordAudioAndroid` | 默认 `true`，即声明 Android `RECORD_AUDIO` 权限 |
| `enableBackgroundRecording` | 默认 `false`，**保持关闭**（会增加前台服务与常驻通知，费电） |

- 运行时权限：`AudioModule.requestRecordingPermissionsAsync()`。
- 录音前需 `setAudioModeAsync({ playsInSilentMode: true, allowsRecording: true })`；**注意**这会切换音频会话，评测结束、返回跟吹页时必须恢复，否则播放行为会异常。
- 录音文件默认落在 **cache 目录**（系统可能在空间不足时清理）。需要长期保留时传 `{ ...RecordingPresets.HIGH_QUALITY, directory: 'document' }`。

### 3.2 音频格式与 PCM 获取（**本期最大不确定项**）

已核实的事实：

- `RecordingPresets.HIGH_QUALITY` = `.m4a` / 44100Hz / 2 声道 / **AAC**（Android `outputFormat: 'mpeg4'` + `audioEncoder: 'aac'`；iOS `MPEG4AAC`）。
- `expo-audio` 的职责是**播放 + 录音到文件**，**不提供实时采样流**，也没有任何音高/频谱分析接口。

而音高检测需要的恰恰是**未压缩的 PCM 采样**。三条候选路径：

| 路径 | 做法 | 代价 | 状态 |
|---|---|---|---|
| **A. 录音直出 PCM/WAV** | 自定义 `RecordingOptions`，Android 侧把 `outputFormat`/`audioEncoder` 设为 PCM 类取值、扩展名 `.wav` | 最省事，纯 JS 可读样本 | **待验证（spike-1）** |
| **B. 录成 m4a 后解码** | 落地 AAC 后解码为 PCM | JS 端无成熟纯 JS 解码方案，需原生库 → 离开 Expo Go | 备选 |
| **C. 换实时音频库** | 如 `react-native-audio-api`，可直接拿 PCM 帧 | 必须 development build + 原生依赖，与"轻量 + Expo Go 可验证"冲突 | 三期再考虑 |

**决策**：一期先做路径 A 的验证。A 不成立再评估 B 的最小实现，**不为了评测功能提前放弃 Expo Go**。

### 3.3 采样参数建议

| 参数 | 建议值 | 理由 |
|---|---|---|
| 采样率 | 16kHz（首选）/ 44.1kHz（若 A 路径只支持此值） | 口琴基频约 200–2000Hz，16k 足够且数据量减少约 63% |
| 声道 | 单声道 | 减少数据量与内存占用 |

## 4. 音高检测

### 4.1 算法选择

- **首选：自相关（ACF）+ 抛物线插值**。实现简单、零依赖、纯 TS；口琴单音信号谐波结构清晰，ACF 效果足够。
- **备选：YIN / MPM**。更抗噪，但实现复杂，留到实测不达标时再升级。

### 4.2 参数

| 参数 | 取值 | 说明 |
|---|---|---|
| 帧长 | 2048 采样（@16k ≈ 128ms） | 低频 200Hz 至少需覆盖 2 个周期以上 |
| 帧移 hop | 160 采样（10ms） | 时间分辨率，兼顾节奏判定精度 |
| 频率搜索范围 | 180–2200 Hz | 覆盖复音琴与布鲁斯琴音域 |
| 置信度门限 | 归一化 ACF 峰值 ≥ 0.6 | 低于门限判为静音或噪声 |

### 4.3 后处理

- 3–5 帧中值滤波，去除单帧离群点。
- 能量门限切掉静音段，避免在静音上算音高。
- 音分换算：`cents = 1200 × log2(f / f_ref)`，`f_ref` 取乐谱期望音高。
- **单音假设的兜底**：多音同响、漏气、环境噪声都会拉低置信度 → 该帧标为"信号不清晰"，**不计入扣分**，避免误伤用户。

### 4.4 性能预算

- 30 秒 @16k 单声道 ≈ 48 万采样；帧移 160 → 约 3000 帧。
- 目标：中端安卓机 **3 秒内**完成分析。
- 策略：一期在 JS 线程跑，超时则降采样到 8kHz / 分片让出主线程；项目已有 `react-native-worklets`，可作为后续提速路径（一期不引入）。

## 5. 对齐策略

**问题**：用户什么时候开始吹、整体是否延迟。不解决对齐，节奏分会全错。

**方案（一期）**：整体时间偏移搜索。

1. 从录音中检测**起音序列**（能量上升沿）。
2. 与乐谱期望起音序列做互相关，取使匹配最佳的偏移 `Δ`。
3. 节奏分只在 `Δ` 对齐后计算。
4. 结果页允许用户手动微调 `Δ`（"我慢了半拍"）。

**不做**：一期不做逐音 DTW 对齐，留作后续增强。

## 6. 评分模型

### 6.1 维度与权重

| 维度 | 权重 | 计算方式 |
|---|---|---|
| 音准 | 40% | 每音取稳定段**中位**音分偏差 |
| 节奏 | 30% | 起音时刻偏差绝对值（对齐后） |
| 稳定度 | 15% | 单音内音分标准差（气息是否稳） |
| 完整度 | 15% | 正确吹出的音数 / 期望音数（漏吹扣分，多吹轻微扣分） |

### 6.2 偏差 → 分数映射

| 音准（音分） | 得分 |  | 节奏（ms） | 得分 |
|---|---|---|---|---|
| ≤ 25 | 满分 |  | ≤ 80 | 满分 |
| 25–50 | 线性下降 |  | 80–250 | 线性下降 |
| > 50 | 0 |  | > 250 | 0 |

> 参考：半音 = 100 音分。25 音分以内人耳基本察觉为"准"。

### 6.3 输出

- 总分 0–100 + 等级（S / A / B / C / D）。
- **逐音结果**（结果页与练习建议的基础）：

```ts
type NoteStatus = 'ok' | 'off-pitch' | 'off-tempo' | 'missed' | 'unclear';

interface NoteEval {
  noteId: string;
  hole: number;
  expectedMidi: number;
  detectedMidi: number | null;
  cents: number | null;
  timingOffsetMs: number | null;
  status: NoteStatus;
}
```

- 小节级汇总，供 UI 高亮。

| 模块 | 位置 | 说明 |

| 音高检测 | `src/core/audio/pitch.ts` | 纯 TS，无 RN 依赖，可单测 |

## 8. 点评生成

### 8.1 一期：规则模板（离线）

输入 `ScoreResult`，按固定结构生成：

1. **总述**：等级 + 总分 + 一句话定性（"整体很稳，音准有进步空间"）。
2. **挑最严重的 2 个问题**：按扣分权重排序，避免罗列。
3. **给一条可执行建议**：如"第 3 小节的 6 孔吸气比标准低约 40 音分，试着把气息放稳、别急着换孔"。
4. **鼓励语**。

优点：零成本、零延迟、无隐私外传、可单测。**对"评价打分"这个诉求，一期已够用。**

### 8.2 二期：LLM 点评（需要决策，且会改变架构）

把 `ScoreResult` 序列化成简短 JSON 交给 LLM，要求输出 3 句以内口语化点评。

| 方案 | 优点 | 代价 |
|---|---|---|
| **BYOK**（用户自带 API key） | 保持"无后端"架构 | 每个用户都得自己申请 key，门槛高 |
| **轻量代理后端** | 体验好 | **打破当前零后端架构**：需部署、鉴权、限流、成本与隐私合规 |

**硬约束**：**绝不能把 API key 打进 App 包里**（可被反编译提取并盗刷）。

**降级**：`commentLlm` 与 `comment` 共用同一接口，无网络 / 无 key / 请求失败时自动回落到规则模板。

> **决策已定**（详见 [ARCHITECTURE](./ARCHITECTURE.md) §7）：选 **BYOK**，不做平台统一 Key；模型**不参与打分**，只做语言化包装；提示词与输出 schema 的版本化规范见该文档 §9。本文 §10 的 **spike-1** 是该路线能否推进的前置条件。

## 9. 集成与 UI

- 新增独立页面 `src/app/eval/[id].tsx`；跟吹页与曲目页各加一个入口按钮。
- **不修改跟吹页核心**：进入评测前先暂停播放、退出评测后恢复音频会话（`setAudioModeAsync`）。
- 复用现有成果：期望音高、期望时序、孔位全部来自 `src/core` 的既有编配结果，评测不重写这套逻辑。
- 历史记录写入 `evals.json`，沿用 `src/store/docStore.ts`，**不引入新的存储方案**。
- 结果页可跳回跟吹页对应小节，形成"评测 → 定位问题 → 重练"的闭环。

## 10. 技术验证清单（动工前必做）

| 编号 | 验证项 | 通过标准 | 失败备选 |
|---|---|---|---|
| **spike-1** | expo-audio 能否录成 PCM/WAV | 录一段口琴，能用 `expo-file-system` 读出可解析的 PCM 样本 | 走 3.2 的 B/C 路径，或退化为"把音频导出到电脑分析" |
| **spike-2** | ACF 音高检测准确率 | 与调音器对比，稳态音误差 < 10 音分 | 换 YIN、加大帧长、加降噪预处理 |
| **spike-3** | JS 分析性能 | 30 秒音频 ≤ 3 秒（中端安卓） | 降采样、分片、worklets 加速 |
| **spike-4** | 端到端对齐 | 故意延迟 0.5s 起吹，仍能正确对齐并给出合理节奏分 | 强化节拍引导 / 允许手动校准 |

> **spike-1 是整条路线的分水岭**，建议第一个做。若它失败，一期的范围与代价需要重新评估。

## 11. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 手机麦克风质量 + 环境噪声 | 检测不准，误判用户 | 置信度门限 + "信号不清晰"状态不计入扣分 + 建议戴耳机/安静环境 |
| 口琴漏气、多音同响 | 单音假设失效 | 同上；必要时提示"请单音吹奏" |
| 低频音（约 200Hz）检测不稳 | 低音区误判 | 加大帧长，保证覆盖 2 个以上周期 |
| JS 端分析耗时 | 等待久、掉帧 | 性能预算 + 分片执行 + worklets 备选 |
| 隐私（录音数据） | 用户信任 | **录音仅在本机处理**，分析完成后默认删除原始音频；UI 明确告知；上 LLM 前先取得同意 |
| 与「整体轻量」约束冲突 | 增加体积与复杂度 | 评测为可选独立页面，默认不启用；分析代码纯 TS 自实现，不引入 FFT 等第三方库 |

## 12. 一期验收标准

1. 权限申请 → 录音 → 30 秒内出分（30 秒音频）。
2. 故意吹错音、漏吹、抢拍，结果页能**准确指出是哪一小节哪个孔**。
3. **完全离线可用**，不依赖网络与后端。
4. `scripts/verify-core.ts` 增加评分算法单测：用合成正弦波 + 已知偏移，断言音准/节奏判定正确。
5. 评测流程不影响跟吹页的播放行为（音频会话正确恢复）。
