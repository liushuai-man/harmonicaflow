## 1. P1：ABC 降号调解析为错误音高

位置：[abc.ts](../src/core/parsers/abc.ts) `keyAccidentals`，约第 47–52 行。

```abc
X:1
L:1/4
K:Db
D E F G A B C
```

实际 MIDI `[63,65,66,68,70,72,61]`，正确 `[61,63,65,66,68,70,60]`。主音先压成 pitch class 后丢失 Db/C# 的拼写差别，Db 被按 C# 的七升号处理，诊断仍是 `full`。应按自然字母的五度位置加升降号偏移计算，并补降号调回归。另有 `K:D dor` 被截掉模式，`F C` 得 `[66,61]` 而非 `[65,60]`。

## 2. P1：ABC 和弦分支遗漏调号

位置：[abc.ts](../src/core/parsers/abc.ts) `readChordNotes`，约第 207 行。

`X:1\nL:1/4\nK:G\nF [DF]` 实际 `[66,65]`，应为 `[66,66]`。单音应用调号，但和弦只看显式记号；相同音进入和弦后变成还原音，最高音选择也可能改变。需让两条路径共享调号与小节临时记号规则。

## 3. P1：替换同格式伴奏不触发重新加载

位置：[audioCache.ts](../src/store/audioCache.ts) `audioFileName/importLocalAudio`，约第 27–41 行；[跟吹页](../src/app/practice/[id].tsx) `handlePickAudio`。

同曲 A.mp3 换 B.mp3 都生成 `audio/<曲目id>.mp3`，返回 URI 相同。`setAudioUri` 值不变，`usePlayback` 与已安装的 expo-audio hook 按 source 复用播放器，不会触发换伴奏归零或媒体重载；还会覆盖正在读取的文件。已用实际模块和内存存储复现 URI 不变，播放器 source 复用由源码确认；旧缓冲的具体听感尚未在 Android 实测。应为每次导入生成独立资源路径。

## 4. P2：伴奏提交失败没有回滚

位置：[library.ts](../src/store/library.ts) `bindAudio`，约第 219–224 行。

故障注入验证：音频字节先落盘、随后 `audio.json` 写入失败，同扩展名时旧引用仍在但内容已经被覆盖；不同扩展名时新文件变成孤儿。旧文件清理失败又会使已经提交的新绑定抛错，UI 不刷新。应先准备独立文件、提交引用；提交失败回收新文件且保留旧绑定；提交后的清理失败单独处理。

## 5. P2：MusicXML 和弦最高音继承了低音的延音标记

位置：[musicxml.ts](../src/core/parsers/musicxml.ts) 和弦最高音替换分支，约第 238–241 行。

连续两组 `C4+G4` 四分和弦，仅 G4 用 tie start/stop 连接。实际生成两个 480 tick 的 G4，应为一个 960 tick 的 G4。替换最高音只更新 midi/时值，没有替换 tieStart/tieStop/tieContinue；反之低音带 tie 时可能错误合并高音。应保留被选中音自己的延音属性。
