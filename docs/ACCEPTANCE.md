## 1. 验收分级

按「**成本从低到高、能低成本拦住的绝不花钱拦**」分三级。功能验收需逐级通过；真机诊断和只读视觉方案探索可提前进行，但不能以诊断代替验收。纯文档变更见 §2。

| 级别 | 名称 | 覆盖什么 | 执行方式 | 触发时机 |
|---|---|---|---|---|
| **L1** | 静态门禁 | 类型、规范、纯函数边界、依赖与配置 | 四条命令（§2） | **每次提交前**，CI 自动跑 |
| **L2** | 廉价验证 | Metro 能否解析并打包、脚本断言 | `expo export` / `npm run verify` 断言 | **每个任务完成时** |
| **L3** | 完整验证 | 真机观感、音频听感、性能、离线 | 真机手动 + 用户体验 | **每个任务完成时**；发版前跑全量 |

> 风格偏好由用户拍板；布局、动作语义、状态与几何包含可测试的客观要求，纯函数用脚本断言，实机可读性/触控/动画另验。不能把全部视觉问题归为主观，也不能以脚本通过替代真机。

## 2. 通用门禁（L1）

四条命令**全部要绿**，CI（`.github/workflows/ci.yml`）已接入同一套：

| 命令 | 管什么 | 失败意味着 |
|---|---|---|
| `npx tsc --noEmit` | 类型 | 类型不安全，直接阻断 |
| `npm run lint` | 代码规范 | 有死代码、隐患写法或不一致风格 |
| `npm run verify` | 解析 / 编配 / 简谱 / `core/visual` 几何 | **纯函数层回归**，最高优先级 |
| `npx expo-doctor` | 依赖与配置与 SDK 匹配 | 依赖漂移，出包可能失败 |

**判定**：四条命令退出码均为 0，且 `verify` 输出中**没有 `✗`**。
`verify` 表格里表示「不可吹音」的 `✗` 属于**数据而非失败**，以脚本 `exitCode` 为准。

**文档专用变更**：只修改 Markdown 且未改配置/代码/依赖时，检查差异、相对链接、章节引用与跨文档一致性，不要求启动构建或真机回归。记录“文档校验通过，功能未验证”；这不等于任一 T 任务通过，也不替代后续代码变更的四门禁。

### 记录规则

1. **不通过项必须写「卡在哪一步、报什么错」**，不能只写「不通过」。
2. **主观项由用户拍板**，Agent 不代替用户判定「好看 / 不好看」。
3. **遗留问题必须标注是否阻塞**，阻塞项不修完不进入下一任务。

## 7. 缺陷分级与判定规则

| 级别 | 定义 | 处理 |
|---|---|---|
| **阻塞** | 崩溃、数据丢失、音高/时序/编配错误、离线不可用、核心孔位/动作误辨、关键控件被裁切或不可操作、代码任务 L1 失败 | 修复后才能通过受影响任务 |
| **非阻塞** | 不影响阅读与操作的装饰细节、次要文案 | 记录遗留；不代表主观风格已定档 |

**总判定**：代码/功能任务（纯文档按 §2）**只有同时满足**下列条件才算验收通过 ——
① L1 四条命令全绿；② 该任务 `§3` 表格中**所有「阻塞」性质的验收项**通过；③ 主观项已由用户拍板；④ §4 回归清单全通过。
