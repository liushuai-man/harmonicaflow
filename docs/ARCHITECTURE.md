- 版本：v0.3.0
- 日期：2026-10-08
- 状态：当前边界 + 条件性规划；后端、桌面壳、同步、评分与 AI 尚未落地。

> 当前交付主线是 Android 本地练习。Web 有技术基础，但尚未作为完整电脑端开发与验收；博客联动是博客中的独立项目展示模块。本文定义扩展条件，不授权立即创建后端、拆包或购买服务器。当前任务以 PLAN 为准。

## 1. 目标与约束

### 1.1 产品与工程目标

| 目标 | 当前决策 | 触发条件 |
|---|---|---|
| Android 练习 | 默认离线，优先正确性、可读性、品牌统一与真机体验 | 当前主线 |
| 电脑使用 | 优先验证 Web 核心流程，不预先选定桌面壳 | Android 基线稳定后开展适配 |
| 博客联动 | 独立展示模块负责介绍、演示、源码与体验入口 | 博客技术栈与展示深度确定 |
| 自动同步 | 当前无账号、无后端仍可练习 | 确有跨设备自动同步需求 |
| AI 点评 | 本地评分优先，文本点评为可选增强 | T5/T6 通过后启动 T7 |

### 1.2 稳定约束

- 核心解析、编配、音高和几何不依赖 React/RN/Expo/Node/Electron 平台 API。
- 本地导入、编配、跟吹不依赖网络；可选服务失败不能阻塞已有本地能力。
- 不默认上传乐谱与录音；联网能力单独定义授权、数据范围、费用和离线退路。
- 维持现有依赖预算。本次不新增依赖；未来新增运行时依赖需说明替代方案、体积/原生成本与维护收益并取得批准。
- 本机不安装 Java/Android Studio、Android 出包走 EAS，是开发环境约束，不推导为服务端语言禁令。
- 默认体验完整，常用与高级偏好分层。个性化不得破坏孔位、吹吸、时序或可读性；不把每个视觉细节做成开关。

### 1.3 非目标

当前不做社交、排行、插件市场、iOS、自动云同步与实时 AI。不因远期规划创建空目录、空接口或服务骨架。

## 2. 当前结构与部署边界

    Android 页面 / 未来 Web 页面
           ├── 呈现组件 + 主题令牌
           ├── 播放控制与平台音频适配
           ├── 曲库与偏好 → docStore 本地 I/O
           └── core 解析 / 编配 / 音高 / 视觉几何

    博客展示模块 → 链接或可选嵌入独立 Web 体验
    未来同步 / AI → 可选接入，不进入离线核心链路

部署建议（不是本次发布授权）：

- Android 独立构建和分发；未来 Web 优先静态托管，复用已有发布基础并验证路由、资源路径、缓存更新与可达性。
- 博客保持自己的技术栈和发布流程，先以介绍和体验入口联动；嵌入交互需另验尺寸、焦点、音频和宿主限制。
- 展示模块不复制解析/编配算法，也不因此建立共享账号、数据库或 monorepo。
- 当前不购买服务器。有服务端需求后再比较托管服务、函数或自管服务器；构建服务不等于应用运行时后端。
- 公开体验曲目使用稳定公开 ID，不分享设备私有文件 URI。公开素材与用户私人曲库分开。

## 3. 模块划分与依赖方向

### 3.1 当前目录先保持不动

| 模块 | 责任与依赖 |
|---|---|
| core/ | 领域模型、解析、编配、纯几何；可用已有纯 JS 库，不读设备、网络或存储 |
| player/timing.ts | 纯时间换算，仅依赖 core |
| player/usePlayback.ts、timeSource.ts | 当前已含 React/Reanimated/Expo 音频适配，不属于跨端纯核心 |
| store/ | 曲库、偏好、缓存，经 docStore 读写；现有封面下载是明确的可选联网路径 |
| theme/ | 色彩、皮肤、令牌纯数据；ThemeProvider 连接偏好与平台外观，纯令牌不依赖存储或 AI |
| ui/、app/ | 呈现与操作编排，不反向被 core 引用 |
| 未来 services/ | 远端调用与同步编排；由用例调用，不由 docStore 自动触发 |

### 3.2 按职责并列依赖

    页面/用例编排 → UI、播放适配、仓储、可选服务
    UI → 主题纯令牌、core
    播放适配 → timing、core、平台音频
    仓储 → docStore、core
    可选同步编排 → 仓储、远端 API
    各适配层 → 领域契约；core 不反向依赖适配层

主题不依赖 AI，存储不依赖提示词。共享语义、确定性算法与纯令牌；不同平台允许不同密度、输入方式和必要组件。先验证 Expo Web 的组件复用，不预先要求全部重写，也不强求像素一致。

文件、持久化数据和远端响应在进入领域逻辑前校验。TypeScript 类型不能替代运行时校验；优先复用纯函数，不为此预先新增库。

### 3.3 何时拆包

第二个独立消费者确需共享发布/构建边界时才评估 npm workspaces。仅新增同仓库 Web 平台或博客链接不自动触发拆包。按实际复用抽取 core、契约、纯令牌和存储接口，平台实现分别保留；不建立无明确职责的 shared 杂物包，core/visual 只保留一个来源。

每次只迁一个边界，保持 Android 独立构建、离线运行与门禁通过。先用已有 lint 与脚本守边界，额外开发工具按实际需求评估。

## 4. 故障隔离与降级

| 边界 | 要求 |
|---|---|
| 构建 | 移动端不引用桌面壳/服务端专用代码，未来端不成为 Android 构建前置 |
| 运行 | 网络失败保留导入、编配、跟吹与本地曲库；评分仅在 T6 实现后适用 |
| 发布 | Android、未来 Web、博客独立发布；OTA 和桌面更新需另行配置 |
| 数据 | 本地数据支持独立使用；同步不得因云端故障静默清空本机 |
| AI | 缺 Key、超时、响应无效时回落到已实现的本地点评，说明实际结果来源 |
| 进程 | 单体模块边界不能保证进程级隔离；CPU/内存故障隔离需额外部署设计 |

错误分为致命失败、部分可用、可重试与用户取消，不能全部吞掉。加载失败不伪装成空曲库，解析失败不生成伪造音符。已有数据保持可恢复，明确提示受影响范围。

## 5. 后端（条件性方案，未实施）

### 5.1 启动条件

自动同步、用户上传共享或服务端计算成为明确需求时才启动；展示公开内容和博客跳转不构成后端需求。

### 5.2 最小边界

按需求增加身份、曲库或同步模块，不一次性创建全套账号、统计、AI 网关。保持单一部署单元是默认候选，具体框架与数据库开工时决定。

### 5.3 模块通信

模块通过明确接口访问，不随意跨模块修改数据。外部 I/O 设置超时、取消与错误处理；不为每个内部函数预建事件总线或熔断器。

### 5.4 契约与版本

优先 HTTP/JSON。两端分别校验各自信任边界；兼容变更增加可选字段，破坏性变更提供显式版本、迁移与旧客户端兼容期。写入重试须幂等。

### 5.5 部署选择

先比较托管服务/函数是否满足需求，再比较自管服务器的费用、备份、监控、恢复与维护时间。凭明确能力限制做决定，不凭“项目要正式”购买服务器。

### 5.6 拆服务触发条件

只有实际的独立扩容、发布或故障隔离需求才拆分；先有测量与维护收益说明，不因远期规划引入微服务。

## 6. 数据与同步（条件性方案，未实施）

### 6.1 本地优先

docStore 保持本地 I/O。同步由独立编排层处理身份、队列、版本、冲突与删除；UI 只消费必要状态，不承诺加同步时页面零改动。

### 6.2 数据契约

区分公开曲目 ID、私人曲目 ID 和内容哈希；跨端不能依赖设备 URI。明确 schema 版本、迁移、校验、资源所有权和导入导出后再实现同步。公开博客素材不自动进入私人同步。

### 6.3 冲突策略

曲谱冲突保留副本；偏好冲突需版本与明确决胜规则，不能直接比较不可靠的设备时钟。删除需要墓碑/恢复策略，队列需要幂等、重试与取消。具体协议在同步任务中验收。

### 6.4 存储可靠性

当前是文件/本地存储与内存缓存，尚无完整事务与恢复机制。未来以单写队列、原子替换或可恢复写入等适合平台的方式处理一致性；测试写入失败、损坏索引和重启。伴奏持久化需经 docStore 复制到持久目录，不能仅保存临时选择 URI。

## 7. AI 层（条件性方案，未实施）

### 7.1 责任拆分

采集/解码适配 → 本地音高与节奏分析 → 确定性评分 → 模板点评 → 可选 LLM 文案。规则评分是唯一分数来源；模型不得修改分数、错误位置或编配结果。

### 7.2 BYOK

延续用户自带 Key 的后期方向，不把平台密钥放入包或网页。移动端安全存储须单独验证；未来 Web 不能照搬原生安全区承诺，需明确密钥驻留、厂商访问限制及是否支持此能力。

### 7.3 Provider 边界

只在第二个 provider 或明确切换需求出现时扩充适配器；共同输入输出不依赖厂商 SDK。接口失败、超时或数据不符合契约时使用本地模板。

### 7.4 成本与隐私

当前不提供平台统一 Key 或 AI 代理。T7 仅在用户主动启用后传结构化数值；音频上传属于另一个需要明确同意的功能。

### 7.5 降级链

无 Key/断网 → 本地模板；远端失败 → 有界重试 → 本地模板。不能把模板结果标为 AI 生成，低置信度录音不生成确定性的错误指责。

## 8. 实时音频分期

先用 T5 验证录音与 PCM，再实现录后评，最后评估实时反馈。不能用未验证的采样能力、延迟或耗电假设反推平台选型。实时能力不能阻塞普通练习。

## 9. 提示词与结果契约

### 9.1 一致性边界

要求评分、错误定位与输出结构一致；不要求不同模型文案完全一致。提示词不能替代运行时校验。

### 9.2 输入

最小结构化评分、错误项与必要练习上下文；含版本与置信度，不默认带完整乐谱或音频。

### 9.3 输出

固定的总结、证据对应的问题项与可执行建议；字段与长度限制在 T7 实施前定稿。数字和位置必须引用输入事实，不能由模型新增。

### 9.4 版本

评分版本、promptVersion 与输出 schemaVersion 分开记录，便于复现与迁移。

### 9.5 评测

固定样本覆盖正确、错音、节奏偏差、噪声、无有效输入与接口失败；结构校验失败回落模板。算法样本先于文案润色。

### 9.6 禁令

不伪造录音证据、诊断疾病或泄露 Key；不允许模型建议自动修改用户谱面，不用自然语言输出直接驱动执行。

## 10. 技术选型 ADR

| 选择 | 当前结论 |
|---|---|
| 后端语言 | 未启动；复用 TS 是优先候选，不因本机无 Java 排除某类服务端 |
| 电脑端 | 优先验证 Web，Electron/Tauri 待真实能力缺口再评估 |
| UI 共享 | 核心语义/纯函数单一来源，组件按适配质量复用 |
| 实时协议 | 普通调用优先 HTTP；有实时需求后再比较 SSE/WebSocket 等 |
| 博客集成 | 独立展示与链接优先，交互嵌入另验 |
| AI | 本地评分优先；音高检测/评分尚未实现，不作为已有资产宣传 |

## 11. 路线图

编号保留用于引用，不表示必须按顺序全部实施。

| 阶段 | 内容与触发 | 交付物 |
|---|---|---|
| P0 | Android 正确性、UI 设计与真机验收 | 离线可练 APK + 证据 |
| P1 | 第二个独立消费者确需共享包 | 单一核心来源，Android 不回退 |
| P2 | 确认自动同步/服务端需求 | 最小服务与离线退路 |
| P3 | P0 基线稳定后推进电脑与博客 | Web 核心流程 + 博客展示入口；桌面壳另决策 |
| P4 | T5 → T6 本地评分 → T7 可选文本点评 | 可信评测与离线退路 |
| P5 | 录后评稳定且确有实时需求 | 经验证的实时反馈 |
| P6 | 实际规模或故障域要求 | 按证据拆服务，可能永远不需要 |

P3 不依赖 P2，博客展示不依赖 P1。具体 UI 定档由用户选择，架构扩展按验收证据推进。

## 12. 风险

| 风险 | 控制 |
|---|---|
| 扩展挤占练习体验 | P0 优先，新增能力独立交付 |
| 多端重复算法 | 共享 core，平台差异放适配层 |
| 配置组合失控 | 默认完整，新增偏好必须有价值与验收 |
| 本地数据丢失 | 迁移、失败恢复、导入导出纳入存储任务 |
| 后端成为必需 | 断网回归，不在渲染/存储底层偷偷联网 |
| 模型或提示词变化 | 固定评分来源、版本与样本，失败回落 |
| 设计文档冒充实现 | 当前/目标/待验证明确标记 |

## 13. 文档职责

PRD 定产品范围，UI_DESIGN 定视觉原则，TECH_DESIGN 记实现与接口，PLAN 定任务，ACCEPTANCE 定验收证据；AI_SCORING 是专项候选方案。修改设计不等于功能已完成，历史摘要不覆盖当前正文。
